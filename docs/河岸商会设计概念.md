## 一、设计目标与资料边界

河岸商会教程首先要让玩家理解：收入怎样变成资金，资金怎样支持行动，以及为什么有时应该把资金留到明天。移动、战斗、建贸易站都应围绕这条经营逻辑展开。

原版解析依据本机安装包的中英文教程文本与 IL2CPP 脚本元数据。本轮没有实际运行原教程；能确认文本内容与相关类型存在，但不能据此认定已经还原全部触发顺序、固定骰子、预置兵力和目标检查值。下文的流程是根据文本线索归纳的教学结构。

## 二、核心规则

### 1. 地图士兵与面板资金

地图上的水獭士兵承担移动、战斗、统治和保护贸易站等职责。面板上代表资金的士兵则是经营资源，两者不能混用。

其他阵营购买服务时，从自己的供应堆支付士兵，进入商会收入栏。这些士兵保留所属阵营，不会变成地图上的水獭军队。

标准开局的商会共有15名水獭士兵，其中4名放置于河流经过的林地，3名放入收入栏作为初始收入；贸易站共9个，按花色放在面板轨道上。开局还需设置三项服务价格。上述士兵数量是总量分配，不是在15名之外另加4名和3名。

### 2. 三个资金区域

| 区域 | 含义 | 何时能用于行动 |
| --- | --- | --- |
| 收入栏 Payments | 顾客刚支付的款项及其他新增收入 | 下一次清晨归集后 |
| 资金栏 Funds | 当前可用资金 | 白天可以使用 |
| 调用栏 Commitments | 本回合已经调用过的资金 | 下次清晨归集后重新可用 |

调用资金是暂时占用：通常从资金栏进入调用栏，下一次清晨重新归集。锻造使用的资金先放到对应锻造轨道空位上，也在归集时返回。

花费资金是支出本金：把代表资金的士兵还给其所属阵营的供应堆，不会在下次清晨自动回到商会。

商会没有固定三个行动的限制。白天可以按任意顺序、次数采取合法行动，受资金、供应、目标及其他规则条件限制。

### 3. 白天行动

| 行动 | 资金代价 | 作用与关键限制 |
| --- | --- | --- |
| 移动 | 调用1资金 | 移动一支部队；沿河移动忽略统治要求，普通道路移动仍遵守通常规则 |
| 战斗 | 调用1资金 | 发起一次战斗 |
| 抽牌 | 调用1资金 | 抽一张牌；商会夜晚没有通常的自动抽牌 |
| 招募 | 花费1资金 | 在河流经过的林地放置一名水獭士兵 |
| 建立贸易站 | 花费2资金 | 两点资金必须属于目标林地的统治者；放置匹配花色的贸易站及一名水獭 |
| 锻造 | 按费用调用资金 | 将资金放到已解锁、匹配花色的贸易站轨道空位上，获得卡牌规定收益 |
| 出口 | 满足锻造条件并支付相同费用 | 放弃牌的通常锻造收益，弃牌并将一名水獭加入收入栏 |

出口必须先满足正常锻造条件，不能用来绕过物品供应不足或已有相同持续效果等限制，也不是在正常收益之外再领取一份奖励。

### 4. 贸易站

- 贸易站是标记，不占建筑格；每块林地最多一个。
- 建站地点不必在河边，但必须存在统治者；仍遵守城堡等禁止放置的规则。
- 两点资金的阵营取决于目标林地的统治者，贸易站花色取决于林地花色。
- 例如，猫咪统治的狐狸林地，需要花费两点猫咪资金，放置狐狸贸易站及一名水獭。
- 不要求把顾客的士兵移到该林地；支出的资金返回所属阵营供应堆。
- 建站连接着即时得分、锻造能力、分红资格和顾客额外购买额度。
- 贸易站被移除时永久离场，不会回到可建造供应，但已解锁的锻造能力保留。

### 5. 服务与顾客

商会公开自己的手牌，并出售三种服务。购买发生在买家自己的清晨开始时，按当前价格支付；正式对局中的购买由买家决定。

| 服务 | 买家得到什么 | 容易误解之处 |
| --- | --- | --- |
| 手牌 | 从商会公开手牌中选择一张购买 | 是付费购买，不是偷取 |
| 租借小舟 | 本回合将河流视为道路 | 不同时获得商会忽略统治要求的游泳能力 |
| 佣兵 | 本回合白天、夜晚，将水獭计入统治与对其他阵营的战斗 | 不能移动这些水獭，也不能用它们完成统治牌胜利；不能用佣兵对商会自身作战 |

买家通常可购买一项服务；每有一块同时存在商会贸易站和买家阵营配件的林地，再增加一次购买额度。购买额度按符合条件的林地计算。

佣兵承担战损时需分摊命中，奇数命中优先由买家承担，并遵守战士先于建筑、标记承担损失等规则。水獭的阵营归属不变，不能因此享受猫咪野战医院等仅针对本阵营士兵的能力。

游侠通过耗竭物品支付，商会据此从自己的供应堆增加水獭到收入栏。游侠不能购买佣兵；其支付窗口先于清晨恢复物品，不能把刚恢复的物品反过来用于已经结束的购买步骤。

### 6. 回合顺序

清晨依次进行：

1. 贸易保护：收入栏为空时，从自身供应堆放入两名水獭，以实际供应为限。
2. 分红：地图上至少有一个贸易站时，按资金栏现有资金每两点得1分，向下取整；不消耗这些资金。
3. 归集资金：将面板上的收入、调用资金及锻造轨道上的资金归入资金栏。

例：资金栏3、收入栏4、调用栏2，先获得1分，再归集为9点可用资金。不能先归集，再按9点计算分红。

白天按资金和合法条件执行行动。夜晚先将超过5张的手牌弃至5张，再调整服务价格；商会没有通常的夜晚自动抽牌步骤。

### 7. 得分与经营风险

| 渠道 | 得分方式 |
| --- | --- |
| 建立贸易站 | 通常每座2分 |
| 清晨分红 | 地图上至少一个贸易站时，资金栏每两点资金得1分，向下取整 |
| 锻造物品 | 获得牌面规定的分数 |
| 移除敌方建筑、标记 | 按通用规则每个1分；移除普通士兵不计分 |

每次贸易站被移除，商会失去资金栏中一半的资金，向上取整。不能把“资金”误解为收入栏、调用栏和资金栏的总和。贸易站的守卫与留钱分红需要结合考虑。

## 三、原版教程解析

### 1. 据文本归纳的主线

| 阶段 | 原版安排 | 教学目的 |
| --- | --- | --- |
| 开店 | 放置4名沿河士兵，三项服务全部定价3 | 建立商会身份，认识价格与收入 |
| 第一天 | 高价没有吸引顾客；使用初始收入，战斗、招募、抽牌 | 对比调用与花费，说明抽牌也要资金 |
| 第一天夜晚 | 小舟降至1，另外两项服务降至2 | 为下一轮真实交易制造原因 |
| 顾客上门 | 猫咪买牌，蜥蜴租船 | 展示商品或能力交付，以及异色收入入账 |
| 第二天 | 用对应阵营资金建站，再锻造、沿河调兵、攻击工坊 | 把收入转为发展和分数 |
| 后续经营 | 解释额外购买额度、佣兵战损、出口与贸易站守卫 | 补充商业网络与风险 |
| 留钱过夜 | 主动保留资金，到下一清晨分红 | 说明少行动也可能有收益 |
| 收尾 | 无人购买时触发贸易保护，转入建站和得分目标 | 从规定操作过渡到自主经营 |

这是文本所支持的主题顺序，不代表已经复原原脚本的每一步运行顺序。

### 2. 值得保留的教学逻辑

让规则成为上一件事情的结果：高价无人买，才有降价；顾客付款，才有异色资金；有了资金，才建贸易站；贸易站落地，才讲锻造和保护；留钱过夜，才解释分红。

原版使用商会角色与顾客对白，呈现猫咪为什么想买牌、蜥蜴为什么需要租船。买卖关系因此成为棋局中的事件，而不只是一个资源数字变化。

### 3. 不能直接照搬的内容

- 中文 `rtf.t3.recruit` 将贸易阻断的取整写成“四舍五入”，英文对应规则是向上取整。
- 小舟和游泳专家的中文描述容易让玩家误以为所有移动都不需要统治；必须区分沿河移动与普通道路移动，以及商会自身能力与买家获得的租船服务。
- `ftt.service.intro.2` 等提示把买牌写成“偷取”，与服务购买规则不符。
- 中文结尾目标出现12与15的矛盾；英文目标文本为15，实际运行检查值仍待核实，不能直接选一个数字作为已确认的原版条件。
- 本机简略供应说明有明显不适合作为完整组件依据的内容，组件数量应与正式规则和面板资料交叉核对。
- 原版默认玩家已掌握基础操作，资金、战斗、锻造之间仍有知识跳跃；本项目需要补足前置解释。

## 四、本项目教程设计

### 1. 总体结构

采用四个连续经营回合，随后接短专项演练。主线保持同一棋盘、手牌和账本，不在每一节重新摆局。专项切换时必须明确告知玩家，并允许返回检查点。

角色关系采用“会长—商会伙计—顾客”。解释具有经营情境，但每句话必须对应当前看得见的资源、行动目的或目标，不以角色对白代替规则说明。

### 2. 连续主线

| 回合 | 玩家需要理解的问题 | 实操安排 |
| --- | --- | --- |
| 第一天：本金怎么用 | 为什么有些钱明天会回来，有些不会？ | 认识三栏；调用一次资金移动、花费一次资金招募，再调用资金抽牌，逐笔观察去向 |
| 第二天：顾客带来发展 | 为什么猫咪的钱，能帮助我们在猫咪地盘开店？ | 第一天夜晚调价；观看顾客真实买牌、租船；下一清晨收款归集；选择对应资金建第一座贸易站 |
| 第二天后半：贸易站有什么用 | 除了即时得分，它还带来了什么？ | 先展示一张真实手牌及其锻造费用，再调用资金锻造；最后调兵保护贸易站 |
| 第三天：经营中的选择 | 继续行动，还是把资金留到明天？ | 展示佣兵交易及其后果；完成必要防守后，有意识地留下至少4点资金 |
| 第四天：兑现经营结果 | 昨天留的钱怎样变成今天的分数？ | 先按旧资金分红，再归集收入和调用资金；随后自主选择一次建站、锻造或其他经营行动 |

第二天拆成两段教学，但仍是同一个真实回合。实际节点数量根据内容长度决定，不把整天塞进一个弹窗。

上表是课程结构，不是已经核算完成的固定局面脚本。进入实现前，要逐笔核对初始本金、顾客支付、资金阵营、调用与支出、招募供应、锻造费用和战损，确保第三天确实能够合法保留至少4点资金。不能靠临时补钱、回合间重置或跳过费用维持教学路线。

### 3. 短专项

| 专项 | 要解决的误解 | 教学方式 |
| --- | --- | --- |
| 无人消费的一夜 | 贸易保护为什么有时触发、有时不触发？ | 对比收入栏为空与非空，观察水獭进入收入栏 |
| 出口还是正常锻造 | 出口并非额外拿一份奖励 | 对照同一张牌的正常收益和出口收益，执行一种后观察放弃了什么 |
| 贸易站遭袭 | 为什么囤钱需要保护？ | 从教学检查点演示损失，展示资金减半、贸易站移出与锻造能力保留 |

贸易阻断专项应使用奇数资金示例，例如5点资金损失3点，直接消除“四舍五入”的错误理解。主线中不应为了讲解损失而突然摧毁玩家刚建立的全部经营成果。

### 4. 交互与表现要求

- 先看到商品，再决定操作。买牌、锻造之前展示真实牌面，允许最小化与再次查看。
- 资金动画显示来源和去向，并保留阵营颜色：调用进入调用栏，花费返回所属阵营供应堆，顾客付款进入收入栏。
- 每个新行动先说明目的与条件。建站前解释为何选这里、为何需要对应阵营的两点资金，不在确认后才补充。
- 顾客必须实际使用服务：租船后展示沿河移动，佣兵购买后展示统治或战斗变化，不能只播放收钱动画。
- 明确固定交易属于教程安排，正式对局的买家不会因为某个价格就必然购买。
- 分红同屏区分“本次计分的旧资金”和“稍后归集的新收入”，不提前合并数字。
- 使用地图聚焦与柔和高亮提示目标，保留移动人数、资金阵营和支付数量的明确确认。
- 每一步完成后展示结果，再推进对白；空操作弹层不得遮挡教学标题。
- 回看解释与重开牌面不重置棋局，不重复扣款，也不产生额外收益。

### 5. 完成标准

教程完成条件应检查玩家实际完成过调用、花费、顾客收款、建站、锻造及跨回合分红，不能只用点击“继续”或达到某个分数代表学会。

玩家在第二天应能认出第一天留下的资金、手牌与军队，并理解昨天的经营决定为什么改变了今天能做的事情。

## 五、实现前待核实项

- 原教程实际运行顺序、局面数值、固定战斗结果和收尾目标检查值。
- 服务价格轨道、资金选择、贸易站花色轨道等原版界面呈现。
- 连续四轮脚本的完整资金与组件预算。
- 佣兵的统治、战损分配、其他阵营能力及特殊胜利边界。
- 贸易站移除后的资金损失、永久移出和锻造能力保留。
- 公开商会手牌对线上联机、PC同屏交接及手机辅助屏的显示要求；公开商品不得被普通手牌遮蔽逻辑误隐藏。
- 购买服务发生在其他玩家回合的流程设计与多人状态同步。
