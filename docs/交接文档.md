## 4. 最后一次改动：阵营选择与准备占用

用户要求解决四人满房时无法互换阵营的问题，已于2026-11-11发布：

1. 等待房间可以自由保存阵营，包括多人暂选同一阵营；下拉选项不再因其他人选择而禁用。
2. 只有已准备玩家占用阵营。点击准备时，服务器事务内检查其他已准备玩家（含人机）；冲突返回409，系统提示“该阵营已有玩家准备，请选择其他阵营”，不更改准备状态。

4. 同阵营候选玩家全部显示，优先展示已准备者，其他人显示待准备，避免人数显示丢失。
5. 加入房间的默认阵营限定于该房间支持范围。

## 7. 必须保留的实现经验

### 网络超时的真实原因与修复

用户反复反馈登录、教程操作10秒甚至30秒无响应，独立测试曾正常；后来在用户日用Edge会话内复现。公网转发链路中，JSON gzip响应出现末尾4字节迟迟不到，JSON内容已解压但response.json仍等待结束。仅延迟res.end未解决。另有keep-alive复用导致约19秒等待的历史问题。

当前JSON API：**不压缩，明确Content-Length，Connection: close**；静态资源仍可gzip，房间SSE独立长连接。请勿为了“优化带宽”直接恢复JSON gzip或普通API keep-alive。需变动时先用日用浏览器、真实公网路径测完整响应，不只测服务器耗时/首字节。

前端读请求及带幂等commandId的命令支持受控重试；request-times诊断在sessionStorage。成功请求日志不含失败请求完整耗时，不能仅凭此判断无超时。最近日用Edge正常GET/教程操作约几十到数百毫秒；后续新网络状态仍需实测。

### 地图控件与图片装饰顺序

`decorate`先于`mountMapControls`。角色选项内图片不能被通用预览监听截走点击；已有`[data-map-choice]`等排除规则。否则会再次出现“角色无法选中/没有确认键”。提交按钮查找需排除领袖预览type=button，防止覆盖预览按钮。

地图重绘要保留建筑、法令卡、目标等草稿；恢复草稿后再克隆选择器。不可用建筑禁用、可用时选首个合法类型；无合法建造应明确原因。最小化后再次选行动/合法目标应重新展开。不能每次重绘重新播放大字入场提示。

手机≤760px地图提示置工具栏顶部单行小字，避免中央大字遮挡目标；游戏提示米白底棕字，系统提示单独样式。

### 弹窗、分数与日志

每次预览新建独立原生dialog，不复用单一dialog替换父内容。子层关闭/Esc/遮罩只关闭自身，恢复父层焦点和滚动。公开玩家面板里的预览按钮需独立绑定。浏览器历史返回键目前未做自定义层级拦截。

左侧分数已合并为“胜利分 N / 30”，保留大数字小分母层次，避免再加重复小字。base-four统一score()写最多100条带seq/reason/delta/total的公共scoreEvents；前端只播新事件，初次加载不补播旧分数。旧规则集未补全此结构化得分原因事件。

日志按每位玩家的一次回合分组，区别于全桌一整轮；不要混淆用户所说的“轮次”。

### 联盟与援助

民愤无匹配牌补偿进入支持者，不是联盟手牌。有基地时不受无基地5张上限限制。专项未复现“有基地不发牌”，已澄清日志及动画，未人工补牌。援助交牌用交付动画，不能将接收方手牌增加一律当抽牌。
