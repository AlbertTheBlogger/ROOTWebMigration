# 蜥蜴神教实现与验收

日期：2026-11-11（Asia/Shanghai）。本轮在v1.1基础上实现蜥蜴神教扩展，新增规则集`root-lizard-cult-v6`、状态schema 6。支持2–4名玩家从猫、鹰、联盟、游侠、蜥蜴五个阵营中选择，各阵营限一人；没有扩为五人房间。

## 规则依据及差异

采用[Leder Games 2025-10-13 Law of Root](https://cdn.shopify.com/s/files/1/0106/0162/7706/files/Root_Base_Law_Oct_2025.pdf?v=1774903756)第10章和共同规则。原安装包本地化、类型、数值及资源用作静态交叉证据，未实际逐项操作原数字版核验。

明确采用2025规则：起始角落必须未被其他阵营占用，尽可能选择已有起始角落的对角；失魂花色平票或无非鸟牌时，原花色保持并成为憎恨。此处与较早规则文本不同，不混用“平票保持原面”的旧描述。

原包LizardCultPlayer.GetTrackInfo静态窗口支持五座花园的得分序列0、2、2、3、4，以及每花色第二座花园的抽牌加成。研究输出位于`research/lizard/`；GetTrackInfo/GetGardenVP使用下一映射方法地址作为有界窗口，不能把窗口内全部指令宣称为已恢复的独立函数体。AdditionalDraws和initialize的局部反汇编仅为辅助证据。

## 实现范围

| 范围 | 当前行为 |
| --- | --- |
| 开局 | 25战士、每花色5花园；玩家选择合法角落，放4战士及匹配花园，邻接清理地各放1战士；选择初始被逐者 |
| 花园统治 | 存在蜥蜴花园即由蜥蜴统治，优先于飞鹰平局统治及敌军数量 |
| 失魂堆 | 蜥蜴在场时，各阵营花费/弃置的牌进入公开失魂堆，含统治牌；清晨清空时统治牌才进入可换取区；失魂堆不直接用于洗牌补充牌堆 |
| 被逐者 | 忽略鸟牌统计唯一最多花色；更换花色时取消憎恨，维持花色时成为憎恨；清空失魂后进入密谋 |
| 仪式 | 展示匹配非鸟牌招募/建造；花园建造需统治、空格及供应；鸟牌仅可展示献祭，不能当作仪式万能牌 |
| 公开展示 | 展示牌移出手牌、对所有玩家公开；不能重复用于白昼其他支付、伏击或民愤；夜晚收回 |
| 得分 | 花费匹配牌，按当前该花色花园数得分；每花色每回合限一次，零花园不得得分；支持30分即时胜利 |
| 复仇/恐惧 | 防守战斗损失的蜥蜴成为侍僧；进攻、弩击及起义等非防守战损不因此获得侍僧。每座花园被拆时从未展示手牌随机弃1张，服务器保存结果 |
| 密谋 | 圣战、转化、圣化，正常成本2/2/3侍僧，憎恨减1；仅在被逐者花色行动/起点发动 |
| 圣战移动 | 遵守道路与统治规则，选择起点/终点/数量；先处理目的地民愤，再选择是否追加目的地战斗，追加战斗不重复支付侍僧 |
| 转化 | 替换敌方战士；支付返回储备的侍僧可用于放置新兵；猫医院在替换后结算；不可转化游侠棋子，不可在城堡放蜥蜴 |
| 圣化 | 替换敌方建筑并放匹配花园，可利用刚腾出的满格；移除建筑得1分；拆联盟基地继续处理支持者/长官损失；检查花园供应及城堡放置禁令 |
| 夜晚 | 收回展示牌，处理鞋匠；只激活被逐者花色花园锻造，同一花园每回合限用一次；抽1张加每花色已揭开的加成，弃到5张 |
| 跨阵营/卡牌 | 复用共同战斗、伏击、持续效果、游侠关系、联盟民愤、猫医院及统治/结盟框架 |

## 产品与兼容

新增模式“扩展标准局 · 蜥蜴神教”，可在创建房间或等待房间中选择。等待房间的规则持久化并通过SSE同步，支持的阵营由服务器返回；更换规则会取消真人准备，存在不兼容阵营时拒绝切换。既有重复暂选和准备占用机制保留。

地图显示蜥蜴战士、花园和统治标记；侍僧、被逐者、憎恨、三花色轨道、公开展示牌及失魂堆可在本人/公开面板查看。个人库存顶部补充关键状态摘要，圣战移动接入现有地图起终点及数量控件。

房间人机支持蜥蜴，可完成开局、仪式、密谋、插入选择及夜晚。策略仍简单，优先得分/建花园及可用密谋，不代表成熟战略AI。

v5引擎文件保持不变。v6在独立文件中继承该规则实现后扩展，旧局仍按原ruleset/schema路由；无数据库迁移，也不把旧局强制升级。后续涉及共同规则的修复应评估v5/v6分别处理，不能假定改一份会自动修改另一份。

新增3张原美术（战士标记、花园、阵营插画），来源、路径ID和哈希见`research/lizard/assets.json`；均排除在MIT范围外。新增程序/测试/工程文档逐文件列入MIT清单。

## 验收证据

- `tests/lizard-cult.test.mjs`共17项：合法组合开局、旧版本路由、统治优先、失魂与统治牌、憎恨、仪式限制、展示隐私、花园供应、得分、医院、基地损失、防守复仇、随机弃牌、民愤顺序、夜晚锻造/抽牌、空牌堆、选择序列化与过期ID。
- 其中4种包含蜥蜴的四人组合，各通过人机策略自然获胜；每一步检查50/54张实体牌守恒及唯一性、战士/侍僧总供应、花园上限和建筑空位，中途反复JSON保存恢复。这是引擎流程验收，不能当作原数字版行为一致性或策略强度结论。
- `tests/lizard-http.test.mjs`共2项：真实HTTP房间、权限/准备冲突、规则持久化、幂等开局选择和多次服务重启；一蜥蜴真人席位与三房间人机自然结束，验证下一局与删房。日志`audit/lizard-http-tests.txt`记录的一局为第10轮联盟胜利，此结果不代表所有自然对局的固定胜者。
- 完整157项Node回归通过，最终结果见`audit/lizard-all-tests.txt`。早先沙箱内运行部分HTTP测试因本地连接EACCES失败，不作为产品失败；有效回归使用工具权限机制运行。
- 最终桌面UI：独立headless Edge，1366×900，蜥蜴真人席位通过正常控件158次操作，第16轮自然结束；覆盖仪式、转化、圣化、圣战移动、锻造、弃牌、公开详情、重启续局、下一局。无页面错误。`audit/lizard-browser.txt`及同名目录报告/截图。
- 最终移动UI：Edge模拟390×844，30次正常操作进入第4轮，覆盖圣战移动、展示/献祭、建造、锻造、公开详情、重启，无横向溢出或页面错误。`audit/lizard-mobile.txt`及同名目录。未验证iOS/Safari或真实手机。
- 现有五章39节点教程通过89次UI命令回归，无页面错误，`audit/lizard-base-tutorials.txt`。本轮没有新增蜥蜴教程章节。
- 新增代码语法检查，旧v5文件与基线一致。未操作真实玩家对局，全部HTTP/浏览器测试使用独立临时数据库。
