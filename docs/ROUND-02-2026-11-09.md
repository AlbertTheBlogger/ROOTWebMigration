## 原版证据

原始 GameAssembly.dll 的 SHA-256 继续匹配既有研究基线。

- 定位 `StandardDecks..cctor`，导出 16 组静态列表与每次加入牌表的代码地址。
- `DrawDeck` 包含 50 个条目、38 种卡牌原型，包含 5 张伏击牌和 2 张铠甲兵。`ExilesAndPartisansDeck` 为 50 个条目、42 种原型。
- `DominanceCards` 独立保存四种统治牌，`sharedInit` 中存在条件引用。DrawDeck 的 50 条记录与该独立列表分别保留，尚未恢复完整统治规则。
- `ItemsOnlyDeck` 含 20 种物品牌原型。逐张从构造函数核对制作成本与得分，得分同时和原版英文物品文本交叉校验。
- 从 `TuberPlaymat.sharedInit` 的 12 次 createItem 调用与 `ItemTypes` 元数据常量核对初始制作供应，背包 2、靴子 2、弩 1、锤子 1、剑 2、茶 2、钱币 2。
- 补齐三个旧研究样本的牌数证据，铁砧 1、狐狸伏击 1、铠甲兵 2。铁砧和铠甲兵成本为一个狐狸制作点。伏击不可制作，其制作成本保持 null 并标记不适用。

主要证据位于 `research/deck/deck-composition.json`、`card-catalog.json`、各构造函数 JSON，以及 `research/baseline/enum-evidence.json`。静态指令窗口按下一个映射方法地址限定，报告保留窗口边界和 PE runtime-function 边界。窗口导出不等于恢复完整控制流，原游戏动态运行仍待验证。

## 开发结果

新增可选规则版本 `root-card-lab-v3`，存档 schema 3。

- 新局使用已提取的 DrawDeck 50 条组成，并复用已有洗牌、抽牌和战斗引擎。
- 实现 20 种物品牌制作，对应七类物品，支持两制作点配方、设施使用次数、物品供应消耗、弃牌、猫得分与鹰的蔑视贸易／建造者得分。
- 支持伏击、铠甲兵和已有战斗决策持久化。
- 其他 23 张牌的特殊效果暂未实现，界面标记效果待实现。它们可以作为花色支付或政令使用，不能发动未实现的制作效果。
- 房间规则选择中增加“原版牌组与物品制作 v3”。默认选择继续为 v2，需由房主明确选取 v3。
- v1、v2 存档继续使用各自规则。固定猫鹰开局与地图沿用 v2，本轮没有扩展房间人数。

运行数据位于 `backend/data/base-card-catalog.json`，只包含牌名、数量、花色、支持状态和已核验配方。研究汇编、原始素材与完整本地化文本均不进入部署包。

- 本地 54 项 Node 测试通过。
- 9 项 Python 研究测试通过，包括原版静态列表、已知卡牌数量、配方解析与未知写入拒绝。
